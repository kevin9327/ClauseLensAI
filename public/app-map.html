ClauseLens Studio — Architecture & Code Tour Map

1. The Pieces (How ClauseLens Studio Is Organized)

public/index.html

Split-pane Contract X-Ray Viewer on the left and the 3-Tab Negotiation Studio (Redline Cards, Counter-Offer Email, Custom Scanner) on the right.

public/app.js

State store holding active preset, selected negotiation stance (warm | balanced | firm), accepted clause IDs, and live Fairness Score.

backend/clause_engine.py

Deterministic contract trap detector & stance-calibrated redline library covering IP Grabs, Silent Auto-Renewals, Late Fees, and Unilateral Termination.

backend/server.py

FastAPI service exposing GET /api/presets, POST /api/analyze, and static workbench hosting with automatic offline fallback.

3. Guided Code Tour Route Stops (Click Any Stop to Inspect)

  1. Stop 1 · public/index.html (#contract-viewer & #stance-selector)

    Defines the split-pane layout where verbatim contract text on the left is paired with the 3-tier Negotiation Stance Selector (Warm, Balanced, Firm) and KPI telemetry strip.

  2. Stop 2 · public/app.js (renderContractDocument & computeMetrics)

    Wraps each risky substring in a clickable <mark class="trap-span"> tag, computes the live Contract Fairness Score (0–100) and Protected Dollar Exposure ($14,800), and synchronizes redline toggles with localStorage.

  3. Stop 3 · backend/clause_engine.py (PRESET_CONTRACTS & analyze_custom_contract)

    Holds the 3 real-world contract presets and the regex/heuristic trap scanner that identifies auto-renewals, pre-payment IP grabs, uncapped indemnities, and kill-fee omissions in custom pasted agreements.

  4. Stop 4 · backend/server.py (FastAPI Endpoints & Static Mount)

    Exposes GET /api/presets and POST /api/analyze with Pydantic request validation so both local Python runners and static browser deployments behave identically.
